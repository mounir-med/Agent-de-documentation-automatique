## Circuit GitHub

1. Le coordinateur crée `docs/semaine1/` avec ce `README.md`.
2. Chaque rédacteur travaille sur sa branche (`semaine1/descriptif`, `semaine1/dataset`, `semaine1/maquette`, `semaine1/pipeline`) et ouvre une pull request.
3. Le relecteur vérifie les critères d'acceptation, commente, puis approuve.
4. Une pull request n'est fusionnée qu'après approbation. Les quatre livrables sont fusionnés sur la branche principale avant la date limite.
5. Le coordinateur pose l'étiquette `semaine1-remis` sur le dernier commit et prévient l'enseignant.
